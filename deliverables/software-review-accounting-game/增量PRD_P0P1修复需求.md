## 一、项目背景与修复目标

### 1.1 背景

「会计小当家」v2.0.4 已完成产品、架构、代码质量三维度全面评审，整体定位清晰、核心会计逻辑严谨、跨端核心一致，具备良好的交付基础。评审识别出 **P0 级 4 项、P1 级 8 项** 需修复问题，主要集中于跨端架构限制、核心经营逻辑健壮性、跨端扩展能力一致性、体验稳定性与运行性能等关键维度。

### 1.2 修复目标

1. **消除跨端架构核心矛盾**：解决 Tauri 仅支持 Windows 构建的限制，补齐 Capacitor 原生插件配置，保障多平台能力一致，支撑项目多端支持目标。
2. **提升核心经营逻辑健壮性**：重构月末结账损益清空逻辑，消除重复扣除与恒等式失衡风险，补充单元测试保障核心逻辑正确性。
3. **强化体验稳定性与合规引导**：优化硬核模式失败兜底，强化邪道爆雷预警与累计记录展示，平衡收益与合规，提升用户操作顺畅度。
4. **优化工程化与运行性能**：规范构建产物路径与多构建协调机制，优化大型状态对象处理性能，统一多端交互一致性。
5. **提升代码可维护性与可测试性**：建立集中式科目注册表，统一科目管理与校验，为后续功能扩展提供结构化、可验证的产品需求基线。

## 六、实施建议与依赖说明

### 6.1 实施顺序建议

遵循 **P0 优先 → P1 有序 → 协同落地** 原则，建议实施顺序：

1. **P0 级优先实施**：P0-1（Tauri 跨端构建）→ P0-2（结账逻辑重构与单测）→ P0-3（Capacitor 插件配置）→ P0-4（硬核模式失败兜底），优先消除高风险隐患与跨端架构矛盾。
2. **P1 级有序推进**：P1-1（科目注册表）→ P1-2（构建协调脚本）→ P1-3（状态性能优化）→ P1-4（多端交互统一）→ P1-5（邪道预警）→ P1-6（排行榜同步）→ P1-7（核心逻辑单测）→ P1-8（邪道记录持久化），逐步完善可维护性、性能与合规能力。
3. **协同落地**：P0-2 与 P1-7 存在单测覆盖的协同关系，需同步推进；P0-1 与 P1-2 均为构建工程化需求，需协同设计统一方案。
