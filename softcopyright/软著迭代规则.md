# 软著下证后软件迭代怎么办（版本管理规则）

> 适用对象：会计小当家教学软件（登记版本 V2.0.4，登记号待下证）
> 本文件用于指导后续版本迭代时，是否需要重新申请软件著作权（软著），以及如何处理名称/版本变更。

## 一句话原则

**软著保护的是"这一版软件的代码表达"，不是软件的名字，也不是未来的版本。**
迭代要不要重登，取决于"改动有多大"和"有没有换主体"。

---

## 三种情况对照表

| 情况 | 例子 | 是否需要重新登记 | 要做什么 |
|------|------|------------------|----------|
| A. 小版本迭代（同版本软著覆盖） | 2.0.5 修 bug、加一两节课程、优化 UI | **不需要** | 保留开发记录（git 提交、需求文档），原软著继续有效 |
| B. 大版本 / 重大变更 | 3.0 整体重构、更换软件名称、核心玩法重写 | **建议重新申请新软著** | 以新版本重新提交源码+手册，拿到新登记号 |
| C. 换著作权主体（转让） | 公司转让、个人转公司、改名后主体变更 | **必须做转让登记** | 签转让合同 + 向中国版权保护中心提交转让登记申请 |

---

## 情况 A：小版本迭代（最常见）

**判定标准（满足任意一条即属小版本）：**
- 仅修复缺陷（bug fix）
- 新增/调整少量教学内容（如新增 1~3 节课程）
- UI 优化、性能优化、兼容性适配（如新系统、新安卓版本）
- 未改变软件核心功能架构与主要交互逻辑

**处理：**
1. 原软著（V2.0.4）继续有效，无需任何额外登记。
2. 在官网 / 产品页、README 中如实标注当前发布版本（如 2.0.5），但登记号仍写原软著号。
3. 保留好开发过程证据：git 提交历史、测试记录、发布说明，作为"持续开发"的证明。

> 注意：软著不要求每次发版都登记，过度登记反而增加成本。小版本靠"原始登记 + 留存记录"即可。

---

## 情况 B：大版本 / 重大变更

**判定标准（满足任意一条即建议新登）：**
- 主版本号变更（2.x → 3.0）
- 软件名称变更（如"会计小当家"改名）
- 核心引擎 / 架构重写，源码相似度低于原登记版本
- 新增与原软著完全不同的功能模块且占比重大

**处理：**
1. 以新版本（如 V3.0.0）重新准备：前后各 30 页源码 + 用户手册（参考本包内模板）。
2. 提交新软著申请，拿到新登记号。
3. 新旧软著并存，老版本用户仍受原软著保护。

---

## 情况 C：换著作权主体（转让）

**适用场景：**
- 个人开发后成立公司，著作权转给公司
- 公司之间的资产转让、并购
- 软件改名但法律主体变更

**处理（缺一不可）：**
1. 双方签署 **著作权转让合同**（明确转让范围、价格、时间）。
2. 向 **中国版权保护中心** 提交 **著作权转让登记申请**，附合同副本。
3. 转让登记完成后，新主体成为登记著作权人，可凭新证书主张权利。

> 仅内部改名、不改法律主体（如个人名下的软件改个显示名）不需要转让登记，但建议在产品页说明"曾用名"。

---

## 下证后的日常动作 Checklist

- [ ] 在官网 / 应用商店 / README 标注软著登记号
- [ ] 软件名称或版本大变更时，更新产品页说明并评估是否需要新登（情况 B）
- [ ] 换主体前先签转让合同再做转让登记（情况 C）
- [ ] 小版本发版保留 git 记录与发布说明（情况 A 的证据）
- [ ] 每 1~2 个大版本回顾一次软著资产清单，避免遗漏登记

---

## 成本与时间参考（供规划）

- 新申请软著：官费约 0 元（计算机软件著作权登记目前免征官费），下证周期约 1~3 个月（加急更短但需代理机构）。
- 转让登记：同样免费，周期约 1~2 个月。
- 代理机构服务费另计（如需加急或代写材料）。

> 以上为通用参考，具体以中国版权保护中心最新公告为准。
